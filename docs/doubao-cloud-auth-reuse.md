# 豆包云端跨任务登录复用：现场结论与接入要求

日期：2026-09-20。状态：根因已确认，账号级存储接入尚未实现；本文不是修复完成或平台能力承诺。

## 现场证据

用户确认需求为同一个豆包账号在新任务中复用此前完成的合同授权，反馈来自他人的豆包环境。

截图中的 CLI 版本为 `1.9.0-beta.1`；两条只读命令的输出如下：

| 字段 | 现场值 |
| --- | --- |
| `platform` | `linux` |
| `agent_source_type` | `doubaoWork` |
| `evidence_type` | `linux_runtime_environment` |
| `rule_id` | `client.doubao_work.cloud-runtime` |
| `Credential Scope` | `task` |
| `Authorization` | `pending` |

这说明该任务运行在已识别的豆包工作云端，并使用任务级凭证。`pending` 只代表当前授权事务待完成，不能据此判断上一个任务有没有成功授权。本机 PATH 中的旧 CLI 版本与此次远端现象无关。

## 代码原因

- `internal/credential/runtime_local.go` 的共享分支只接受已识别的 macOS/Windows 桌面；云端标记优先保留隔离。
- `internal/credential/store.go` 的普通工作任务分支使用当前工作目录和 `SESSION_ID` 摘要构造凭证目录，并由 `SESSION_ID` 派生加密密钥。任务 ID 改变后，目录和密钥都改变。
- `SKILL_SESSION_WORKSPACE` 分支使用注入的加密密钥与工作区；现有接入没有证明它们在同一账号的新任务之间稳定，也没有将其定义为账号级存储。
- `internal/cli/device_token.go` 的刷新、授权完成和退出锁跟随同一任务范围。跨任务存储接入必须一起处理并发刷新和撤销。
- `1.9.0-beta.1` 的本机共享实现没有覆盖上述云端场景；重新发起授权只能服务于当前可访问的凭证范围。

## 平台对接需要确认的最小契约

1. 是否存在第三方 Skill 可用、同一账号跨任务可读写且不同账号相互隔离的凭证 API 或持久卷？需要官方入口、调用方式、生命周期与隔离保证。
2. 新任务如何证明自己属于此前授权的账号？需要平台验证的身份上下文或仅该账号可访问的存储；任务 ID、操作系统用户名、公开用户 ID 不能单独充当取回凭证的权限证明。
3. 若使用加密文件，密钥如何跨任务安全保留、轮换并注入？不能继续由每次变化的任务 ID 派生，也不能在 Skill 中打包通用密钥。
4. 多任务并发时支持什么协调方式？持久卷需要确认跨执行节点的锁语义；凭证 API 需要条件写入、租约或由服务端串行执行刷新。
5. 用户退出、撤销授权、换账号、离职或持久卷回收时，凭证如何失效与清理？

无需收集真实 Token、device code、账号密码或密钥；提供接口文档、脱敏配置模板及能力保证即可。当前仓库未发现已接入的账号级凭证服务。公开检索没有找到可直接采用的官方接口契约，这不等于平台没有该能力。

## 根据平台契约选择实现

| 方案 | 必要前提 | CLI 与服务端改动 |
| --- | --- | --- |
| 账号级凭证 API／持久卷 | 平台提供账号隔离、跨任务持久化、密钥管理和并发语义 | 增加对应 `credential.Store` 适配；将 profile 恢复、凭证锁、状态、刷新及退出统一到账号范围 |
| 服务端凭证托管 | 每个新任务可取得服务端能验证的账号身份证明 | 服务端按已验证的主体绑定授权并保存凭证，集中处理刷新与撤销；CLI 接入正式定义的认证接口 |

第二种方案仍需要平台身份衔接，不能仅凭客户端传入的账号 ID 返回历史凭证。若既没有账号级持久化，也没有可验证的身份衔接，单独修改 CLI 无法让全新沙箱自动找回此前授权。

在平台契约确定前，不移除任务隔离、不把 Linux 全部当成本机共享、不迁移其他任务凭证，也不把授权文件写入可共享的 Skill 包。

## 实施与验收

实现前先写失败回归：同一平台账号，任务 A 完成授权，任务 B 使用不同任务 ID、工作目录和临时 HOME，仍能恢复 profile 并直接查询，不能再次要求设备授权。

随后必须验证：不同账号不能读取彼此凭证；过期 Token 跨任务并发只刷新一次；任务 A 退出后任务 B 不能继续使用该授权；撤销、存储不可用和写入失败不会退回未验证共享；旧本机共享和旧任务隔离行为不回归。

以上测试通过后，再以真实豆包账号执行 A/B 两个新任务验收。没有完成真实账号的新任务验收前，不宣称解决豆包云端跨任务复用。

本轮已执行现有隔离用例并通过：`TestDoubaoWorkTaskStoreEncryptsAndIsolatesSessions`、`TestLocalUserRuntimeRejectsWeakConflictingOrUnknownEvidence`、`TestCloudMarkersOverrideDesktopEvidence`。这些用例证实当前隔离行为，不能作为跨任务复用已修复的证据。本轮未修改运行代码、未发布或替换安装包。
